# Pratt's Algorithm & Testing - v0.0.1

Software development is hard. Testing both makes it harder and easier.

With unit & integration tests we can iterate while remaining
confident that we're not making regressions on previous behavior.

Obviously, right?

But we've all been there, we want to delivery features, not turn red lights green.

I get it.

Yet while working on `.loi` I was recently reminded of how critical it is for real systems.

There are so many tests we can make, so which ones are have to haves vs nice to haves?

For `.loi`, it's been "everything".

What I mean by that is that we're dealing with pipelines and lots of edge case behavior.

What should this evaluate to?

- `a = -b.c() ^ d * e + f == g && h`

And this?

- `(let a = ((((((-((b.c)())) ^ d) * e) + f) == g) && h))`

Virtually impossible to know at a glance.

So that's why we do need in depth tests over core features.

But on the other hand, sometimes we also just need pulse tests. To make sure

everything's 'wired up' correctly.

## 🧠 Overview.

In order

I've added many tests to `.loi` for both TDD and to ensure I properly implemented Pratt's Algorithm.

The following are the commands I run to start the test runner.



```sh
cargo test

cargo nextest run -E 'test(registry::registry::tests::parsing)'
cargo watch -x 'nextest run -p loi'
cargo watch -x 'nextest run -p loi --lib registry::registry registry::file_meta'

# Run all unless failures
cargo watch -x 'nextest run'

# Run all regardless
cargo watch -x 'nextest run --no-fail-fast'

# Run all and keep sorted
cargo watch -x 'nextest run --test-threads 1 --no-fail-fast'

# Run 1 by file name
cargo watch -x 'nextest run --test _01_literals --test-threads 1 --no-fail-fast'

# Run 2 by file name
cargo watch -x 'nextest run --test registry --test file_meta --test-threads 1 --no-fail-fast'

# Run Regex selected
cargo watch -x 'nextest run --test _0* --test-threads 1 --no-fail-fast'
cargo watch -x 'nextest run --test parser_* --test-threads 1 --no-fail-fast'
cargo watch -x 'nextest run --test lexer_* --test-threads 1 --no-fail-fast'

cargo nextest run --filter-expr 'test(lexer::)'
```
